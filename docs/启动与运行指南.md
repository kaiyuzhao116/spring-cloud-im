## 2. 每次启动（开工五步）

### 2.1 先看现状，再决定起什么

一条命令列出所有关键端口：

```powershell
foreach ($p in 8848,6379,3306,8084,8083,8080,5173) {
    $c = Get-NetTCPConnection -State Listen -LocalPort $p -ErrorAction SilentlyContinue
    if ($c) { "端口 $p : 已运行 (PID $($c[0].OwningProcess))" } else { "端口 $p : 未运行" }
}
```

| 端口 | 是什么 | 没起会怎样 |
|---|---|---|
| 8848 | Nacos | 三个后端全部启动失败（`NacosException: Client not connected`） |
| 6379 | Redis | auth 登录直接 500（会话写不进去） |
| 3306 | MySQL | 登录返回"系统繁忙"（user 查库失败） |
| 8084 | user 服务 | auth 启动能成功，但登录时 `No provider available` |
| 8083 | auth 服务 | 登录接口 404 / 503 |
| 8080 | api-gateway | 前端所有请求 `Failed to fetch` |
| 5173 | 前端 Vite | 页面打不开 |

**注意：Nacos 是最容易被忽视的一个。** 它可能因为关掉窗口、或机器休眠而悄悄退出，端口 8848 一空，后面三个服务全都起不来。

### 2.2 启动顺序

```
① Nacos → ② Redis → ③ MySQL → ④ user(8084) → ⑤ auth(8083) → ⑥ gateway(8080) → ⑦ web(5173)
```

顺序不能乱的原因：**所有服务启动时要连 Nacos，auth 启动/调用时要连 user 的 Dubbo**。反过来先起 auth 会刷一屏 `No provider available`（不致命但很吵，且第一次调用必然失败）。

### 2.3 五步速查（每步都必须看到"成功标志"再往下）

| # | 起什么 | 怎么起 | 必须看到 | 没看到怎么办 |
|---|---|---|---|---|
| ① | Nacos | 双击 `桌面\nacos\启动Nacos.cmd` | `Nacos started successfully in stand alone mode` | 看 `桌面\nacos\logs\start.out` 末尾 |
| ② | Redis | 双击 `桌面\redis\启动Redis.cmd` | 窗口提示"启动中"，之后 `redis-cli ping` 返回 `PONG` | 看 `logs\redis.log` |
| ③ | MySQL | 确认 `MySQL80` 服务为"正在运行" | 3306 可连 | `services.msc` 里右键启动 |
| ④ | user | IDE 点 `UserApplication` 的 main 绿三角 | `Started UserApplication in xx seconds` + `nacos registry ... :8084 register finished` | 检查 ① 是否真的在跑 |
| ⑤ | auth | IDE 点 `AuthApplication` 的 main 绿三角 | `Started AuthApplication in xx seconds` | 若见 `No provider available`，说明 ④ 还没起好 |
| ⑥ | gateway | IDE 点 `ApiGatewayApplication` 的 main 绿三角 | `Netty started on port 8080` + `Started ApiGatewayApplication ...` | 检查 8080 是否被占用 |
| ⑦ | web | 终端 `cd web && npm run dev` | `VITE ... ready`，`Local: http://localhost:5173/` | 端口被占会自动换到 5174，看终端提示 |

### 2.4 全部起完的自检

```powershell
# ① 六个端口都在
Get-NetTCPConnection -State Listen -LocalPort 8848,6379,3306,8084,8083,8080,5173 | Select-Object LocalPort | Sort-Object LocalPort

# ② Nacos 里正好三个服务
curl.exe -s "http://127.0.0.1:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=20&namespaceId=public"
# 期望：{"count":3,"doms":["api-gateway","auth","user"]}

# ③ 端到端能登录
curl.exe -s -X POST http://127.0.0.1:8080/api/auth/login -H "Content-Type: application/json" -d "{\"account\":\"admin\",\"password\":\"123456\"}"
# 期望：{"code":0,...,"accessToken":"eyJ..."}
```

三条全过，说明整套环境可用。浏览器打开 `http://localhost:5173`，`admin / 123456`。

## 3. 第 ①～③ 步：中间件

| 步骤 | 操作 | 预期现象 |
|---|---|---|
| ① Nacos | 双击 `桌面\nacos\启动Nacos.cmd` | 弹出黑窗口，最后出现 `Nacos started successfully in stand alone mode` |
| ② Redis | 双击 `桌面\redis\启动Redis.cmd` | 已在跑会打印 `[OK] Redis 已经在运行: 127.0.0.1:6379`；没在跑会打印启动说明并常驻该窗口 |
| ③ MySQL | `Win+R` → `services.msc` → 找 `MySQL80` | 状态为"正在运行"（服务启动类型已是自动，一般开机就有） |

> **Redis 窗口是"静默"的**：配置里 `logfile "logs/redis.log"`，所以控制台不会滚日志，窗口空白是正常的。
> 只要不关窗口，Redis 就在跑；关掉窗口 = 停止 Redis。想看实时日志：
> `Get-Content "桌面\redis\logs\redis.log" -Tail 20 -Wait`

**验证三个都在**：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8848,6379,3306 | Select-Object LocalPort,OwningProcess
```

**预期**：三行输出，端口 8848 / 6379 / 3306。

## 4. 第 ④～⑥ 步：后端服务（两种方式，任选）

### 方式 A：在 IDE 里点（推荐）

#### A1. 先清理失效的旧配置

顶部 `运行` → `编辑配置`，把下面这些**删掉**（它们指向已删除的类，点了会报"找不到主类"）：

```
SpringCloudApp
WsGatewayApp
ConsumerApplication
GatewayApplication
```

#### A2. 给三个启动类建配置（最快：点 main 左边的绿三角）

| 顺序 | 文件 | 主类 | 端口 |
|---|---|---|---|
| ④ | `user/src/main/java/com/song/user/UserApplication.java` | `com.song.user.UserApplication` | 8084 |
| ⑤ | `auth/src/main/java/com/song/auth/AuthApplication.java` | `com.song.auth.AuthApplication` | 8083 |
| ⑥ | `api-gateway/src/main/java/com/song/apigateway/ApiGatewayApplication.java` | `com.song.apigateway.ApiGatewayApplication` | 8080 |

操作：打开启动类 → 点 `public static void main` 左侧绿色 ▶ → `运行`，IDE 会自动创建同名配置。

**注意：不要加任何程序参数**（尤其别加 `--spring.profiles.active=local`，那是脱离 Nacos 时才用的）。

#### A3. 依次启动，等前一个 Started 再点下一个

**判断标准（必须看到这一行）**：

```
Started UserApplication in 19.279 seconds
```

#### A4.（可选）配一个"一键启动"

`编辑配置` → 左上 `+` → `复合`（Compound）→ 勾选三个配置 → 命名 `全部启动`。

### 方式 B：命令行

三个窗口分别执行（或后台运行看日志文件）：

```powershell
cd "D:\360MoveData\Users\凯宇\Desktop\spring_cloud"

# 窗口 1
java -jar user\target\user-0.0.1-SNAPSHOT.jar

# 窗口 2（等窗口 1 出现 Started 后再执行）
java -jar auth\target\auth-0.0.1-SNAPSHOT.jar

# 窗口 3（等窗口 2 出现 Started 后再执行）
java -jar api-gateway\target\api-gateway-0.0.1-SNAPSHOT.jar
```

### 启动日志里要认的 4 行

| 日志 | 来自 | 说明 |
|---|---|---|
| `Tomcat started on port(s): 8084 (http)` | user/auth | Web 容器就绪 |
| `Started XxxApplication in x seconds` | 三个都有 | **唯一成功标准** |
| `nacos registry, DEFAULT_GROUP user 172.x.x.x:8084 register finished` | user/auth | 已注册，网关能发现 |
| `Netty started on port 8080` | gateway | 网关用 Netty 而不是 Tomcat |

## 7. 停止与重启

### 停止

```powershell
# 停三个后端（按端口杀，最省事）
Get-NetTCPConnection -State Listen -LocalPort 8080,8083,8084 | ForEach-Object {
    Stop-Process -Id $_.OwningProcess -Force
}

# 停前端：Vite 窗口按 Ctrl+C

# 停中间件：双击 桌面\nacos\停止Nacos.cmd / 桌面\redis\停止Redis.cmd
```

### 只重启某个服务

改完代码只需要重启对应服务，不用全起：
- 改 `auth` 代码 → 重启 auth
- 改网关过滤器 → 重启 gateway
- 改 `application.yml` → 对应服务重启（**必须**，配置不是热更新）

## 8. 启动失败对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `NacosException: Client not connected, current status:STARTING` | Nacos 没起 / 8848 不通 | 双击 `启动Nacos.cmd`，浏览器确认控制台能开 |
| `Unable to connect to Redis ... Connection refused` | Redis 没起 | 双击 `启动Redis.cmd` |
| `Communications link failure` / `Access denied for user` | MySQL 没起或密码不对 | 起 `MySQL80` 服务；确认 yml 里是 `root/123456` |
| `Port 8084 was already in use` | 上次进程未退出 | 见下方"端口占用清理" |
| `Web server failed to start. Port 8080 was already in use` | 同上有残留 | 同上 |
| `No spring.config.import property has been defined` | 引入了 nacos-config 却没写 import | 检查 yml 里 `spring.config.import: optional:nacos:xxx.yaml` |
| `找不到主类` / `ClassNotFoundException` | 用了旧的运行配置 | 删掉旧配置重建（见 4.A1） |
| `APPLICATION FAILED TO START` | 后面紧跟 `Description` | 按 Description 定位，多为端口或依赖缺失 |
| 启动成功但登录 500 | MySQL 没起 / Dubbo 找不到 user | 看 auth 日志是否 `RpcException` |
| 页面能开但登录 404 | 没走 Vite 代理 | 必须 `npm run dev` 打开 5173，不是直接开 html |
| 前端登录报 `Failed to fetch` | 网关没起或端口不对 | 确认 8080 在监听、`vite.config.js` 代理指向 127.0.0.1:8080 |

### 端口占用清理

```powershell
# 查是谁占了
Get-NetTCPConnection -State Listen -LocalPort 8080 | Select-Object OwningProcess
# 杀
Stop-Process -Id <上面的PID> -Force
```

## 9. 常见"起来了但不对"的排查顺序

```
登录失败 → auth 日志（有没有走到 BCrypt）
带 token 401 → 网关日志（验签失败？ver 不一致？）
500 系统繁忙 → user 日志 + MySQL 是否在跑
页面空白 → Vite 终端有没有报错；浏览器 F12 Console
```

更细的分层验证见 [手动验证与调试指南](手动验证与调试指南.md)。
