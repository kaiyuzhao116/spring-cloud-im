# 系统设计与实现说明

> 项目：spring_cloud（IM 通讯平台微服务底座）
> 更新时间：2026-10-21
> 当前进度：**登录闭环已跑通**（Vue → 网关 → auth → Dubbo → user → MySQL/Redis）
> 技术栈：Spring Boot 3.0.2 / Spring Cloud 2022.0.0 / Spring Cloud Alibaba 2022.0.0.0 / Dubbo 3.2.10 / JDK 17 + Vue 3

---

## 1. 项目概述

目标是构建一个支撑 IM（即时通讯）的微服务底座：HTTP 走网关，实时消息将来走 Netty 长连接，服务间调用走 Dubbo，异步事件走 RocketMQ（未接入）。

当前已实现的最小闭环：

```
浏览器(Vue) → api-gateway(验签/注入身份) → auth(登录/会话/签发) → Dubbo → user(查库) → MySQL
                                                    ↘ Redis(会话 + 版本号)
```

## 4. 登录链路

### 4.1 时序

```
① 浏览器 POST /api/auth/login {account, password, deviceType}
② api-gateway:8080
     - 路径命中白名单 → 跳过验签
     - 路由 /api/auth/** → lb://auth，StripPrefix=2 后转发 /login
③ auth:8083
     - @Valid 参数校验
     - 失败次数检查 auth:fail:{account}（≥5 直接 429）
     - Dubbo 调 user.getByAccount()
     - BCrypt 校验密码（失败则 INCR 失败计数并返回统一错误）
     - 签发 JWT（精简版：sub / iat / exp）
④ 返回 {userId, nickname, accessToken, expiresIn, deviceType}
⑤ 后续请求 Authorization: Bearer <token>
     - 网关验签 → 注入 X-User-Id → 下游从 UserContext 取身份
```

> **2026-10-22 变更**：token 精简为 `sub / iat / exp` 三个字段，会话写入与版本号校验已从代码中移除。
> 踢人、单端登出、多端区分等能力暂时不可用，恢复方式见 5.3 与第 12 章。

### 4.2 路径对应关系

| 外部（经网关） | 网关处理后 | auth 服务内 |
|---|---|---|
| `/api/auth/login` | `StripPrefix=2` | `/login` |
| `/api/auth/logout` | `StripPrefix=2` | `/logout` |
| `/api/user/profile` | `StripPrefix=2` | `/profile` |

> 网关 `StripPrefix=2`，所以 Controller 里**不要**再写 `/api/auth` 前缀。

## 5. 鉴权设计

### 5.1 职责划分

| 组件 | 负责 | 不负责 |
|---|---|---|
| `api-gateway` | 白名单、JWT 验签、注入 `X-User-Id`、剥离伪造头 | 查库、查会话、签发 token、访问 Redis（精简版后不再访问） |
| `auth` | 密码校验、token 签发、失败计数 | 用户资料维护、会话管理（精简版已移除） |
| `user` | 用户数据，暴露 Dubbo 接口与资料 REST | 密码校验、鉴权 |
| 业务服务 | 从 `UserContext` 取身份，**不解析 token** | — |

### 5.2 JWT 内容（精简版）

```json
{ "sub": "1", "iat": 1792651070, "exp": 1792652870 }
```

| 字段 | 含义 | 网关怎么用 |
|---|---|---|
| `sub` | 用户 ID | 解出后注入 `X-User-Id` |
| `iat` | 签发时间 | 仅用于排查（"什么时候登的"） |
| `exp` | 过期时间 | 验签时自动校验，过期即 401 |

- 三个字段，token 约 180 字符（原四字段版本 228 字符）
- 签名：jjwt 按密钥长度自动选择，当前 57 字节密钥 → **HS384**
- payload 是 base64url **明文可读**，因此不放密码、手机号、权限明细
- 生产建议改 RS256（auth 持私钥，网关只放公钥）

### 5.3 失效机制（当前：无服务端失效）

精简版移除了 `sid` 与 `ver`，因此：

| 能力 | 现状 | 原因 |
|---|---|---|
| 主动踢人（单端/全端） | ❌ 只能等 token 过期（≤30 分钟） | token 里没有可对账的标识 |
| 退出登录 | ❌ 仅客户端删除 token，服务端无感知 | `logout` 是空实现 |
| 多端区分 | ❌ 无 `sid` / `dev` | 网关不再注入 `X-Session-Id` / `X-Device-Type` |
| 封号（DB `status=0`） | ⚠️ 只影响新登录，已发 token 仍有效到过期 | 网关不查库 |

**恢复能力的三步**（需要时按顺序加）：

1. `JwtManager.sign` 增加 `.claim("sid", sid).claim("ver", ver)`
2. `AuthService` 恢复写会话（`HSET auth:sess:{sid}` + `SETNX auth:user:{uid}:ver 0`），并把两个值传给 `sign`
3. `AuthGlobalFilter` 恢复读取 claims 并比对 Redis 的 `ver`

> 完整设计（五个 key、两级失效、`revoked` 黑名单）见 git 历史中的旧设计稿，或按第 12 章逐步补。

### 5.4 网关校验成本

每请求 = **1 次本地验签（约 0.1ms）**，不访问 Redis、不调用 auth。
这是精简版最大的收益：网关完全无状态，扩缩容无成本。

代价是"无法即时撤销" —— 需要即时踢人时必须在网关加回 Redis 版本号比对。

## 6. 数据模型

### 6.1 MySQL

```sql
-- db/schema.sql
CREATE TABLE sys_user (
  id            BIGINT UNSIGNED AUTO_INCREMENT,
  account       VARCHAR(64)  NOT NULL,          -- 登录账号，唯一
  password_hash VARCHAR(100) NOT NULL,          -- BCrypt cost 10
  nickname      VARCHAR(64)  NOT NULL DEFAULT '',
  avatar        VARCHAR(255) DEFAULT NULL,
  status        TINYINT      NOT NULL DEFAULT 1, -- 1 正常 0 禁用
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id), UNIQUE KEY uk_account (account)
);
```

测试数据：`admin / 123456`（BCrypt：`$2a$10$oAhOz9YQMsvL...hxLo6`）

连接：`jdbc:mysql://127.0.0.1:3306/spring_cloud`，root/123456，物理文件
`C:\ProgramData\MySQL\MySQL Server 8.0\Data\spring_cloud\sys_user.ibd`

### 6.2 Redis

| key | 类型 | TTL | 状态 | 说明 |
|---|---|---|---|---|
| `auth:fail:{account}` | STRING 整数 | 15 分钟 | ✅ **在用** | 登录失败计数（防撞库） |
| `auth:sess:{sid}` | HASH：`uid/deviceType/ip/ua/loginAt/lastSeen` | 7 天 | ⏸ 停用 | 精简版后代码不再写入；历史遗留会自然过期 |
| `auth:user:{uid}:ver` | STRING 整数 | 无 | ⏸ 停用 | 精简版后代码不再读写；恢复"即时踢人"时需要它 |

> 停用的两个 key 对应的能力与恢复步骤见 5.3；Redis 里已有的旧 key 不影响运行，可以手动清掉：
> `redis-cli --scan --pattern "auth:sess:*" | xargs redis-cli del`（或忽略，等 TTL 过期）。

> 尚未实现：`auth:user:{uid}:sessions`（设备名册）、`auth:rt:{sid}`（refreshToken）、`auth:revoked:{sid}`（临时黑名单）。

## 8. 关键配置

### 8.1 JWT（auth 与网关必须一致）

```yaml
# auth
jwt:
  secret: spring-cloud-im-demo-jwt-secret-key-please-change-in-prod
  expire-seconds: 1800
  session-ttl-seconds: 604800
  max-fail-count: 5
  fail-window-seconds: 900

# api-gateway
gateway:
  auth:
    secret: spring-cloud-im-demo-jwt-secret-key-please-change-in-prod
```

### 8.2 Dubbo（避免与服务名冲突，必须这么配）

```yaml
# 提供方
dubbo:
  application:
    name: user
    register-mode: interface      # 只做接口级注册
# 消费方（auth / ws-gateway）
dubbo:
  application:
    service-discovery:
      migration: FORCE_INTERFACE
```

### 8.3 数据源与 Redis

```yaml
spring:
  datasource:            # 仅 user 模块
    url: jdbc:mysql://127.0.0.1:3306/spring_cloud?useSSL=false&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: "123456"
  data:
    redis:               # auth / api-gateway
      host: 127.0.0.1
      port: 6379
```

### 8.4 本地无 Nacos 模式

各服务已内置 `local` profile：`--spring.profiles.active=local` 时关闭 Nacos 并把 `dubbo.registry.address` 设为 `N/A`，可脱离注册中心启动 Web 部分。

## 10. 已验证用例

| 用例 | 结果 |
|---|---|
| 网关登录 `admin/123456` | `code=0`，返回 `userId/nickname/accessToken/expiresIn` |
| token payload 解码 | 仅 `sub / iat / exp` 三个字段 |
| 带 token 拉资料（连续 4 次） | 4/4 成功，昵称「管理员」，验证负载均衡不再打到 Dubbo 端口 |
| 不带 token | 401 `未登录或登录已失效` |
| 伪造 token（改任意字符） | 401 `登录已失效，请重新登录` |
| 只伪造 `X-User-Id` 不带 token | 401（网关先验签，头会被覆盖） |
| 直连 user 不带 `X-User-Id` | 200 + `code=401 缺少身份信息`（服务侧业务错误） |
| 密码错 5 次 | `code=429 失败次数过多`（第 6 次密码正确也拒绝） |
| 前端 Vite 代理 | `/api/auth/login` 经 5173 代理到 8080 成功 |

> 精简版后已失效的用例（需要恢复 `sid`/`ver` 才能再验）：`INCR ver` 后旧 token 立即 401、`DEL sess` 后仍 200 的 30 分钟窗口。

## 11. 踩坑记录

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | 网关报 `invalid version format: UNSUPPORTED` | Dubbo 3.2 应用级注册把 `user` 注册到 20882，与 Spring Cloud 的 `user:8084` 撞名，`lb://user` 轮询打到 Dubbo 端口 | 提供方 `register-mode: interface`，消费方 `migration: FORCE_INTERFACE` |
| 2 | 下游一直报"缺少身份信息" | `default-filters: RemoveRequestHeader` 在 GlobalFilter 之后执行，删掉了刚注入的头 | 去掉 default-filters，剥离逻辑放在 `AuthGlobalFilter` 内部（先 remove 再 set） |
| 3 | 编译报 `NoSuchFieldError: JCTree$JCImport.qualid` | Boot 3.0.2 锁 Lombok 1.18.24，不支持 JDK 21 | 父 pom `dependencyManagement` 显式指定 1.18.30（BOM 内属性无法被外部属性覆盖） |
| 4 | common 模块编译找不到 `HandlerInterceptor` / `HttpServletRequest` | 该模块只依赖了 `spring-boot-starter` | 增加 `spring-webmvc`、`jakarta.servlet-api`，均为 `optional`，不传递给 WebFlux 网关 |
| 5 | 双击 `启动Redis.cmd` 报 `'动日志...' 不是内部或外部命令`，并反复刷屏 | 脚本存成 UTF-8 + LF，且含 `if (...)` 多行括号块，cmd 按代码页逐字节解析时把中文行切断 | `.cmd` 统一用 **GBK（代码页 936）+ CRLF**，并避免多行 `if (...)`，改用 `goto` 跳转 |

## 13. 已知限制（当前版本）

| 限制 | 影响 | 是否需要尽快处理 |
|---|---|---|
| **无法即时踢人**（token 无 sid/ver） | 封号后已发出的 token 仍可用到过期（≤30 分钟） | 视业务，有管理需求就要补 |
| **退出登录是客户端行为** | 服务端无感知，旧 token 仍有效 | 同上 |
| **无 sid / dev** | 后台看不到设备、无法单端下线、下游拿不到设备类型 | 同上 |
| 无名册 | 后台无法列出"某用户有哪些设备" | 做后台时 |
| 无 refreshToken | 30 分钟后必须重新输账号密码 | 上生产前 |
| HS384 共享密钥 | 网关需持签发密钥，建议换 RS256 | 上线前 |
| 登录无 IP 限流 | 只按账号计数，密码喷洒防不住 | 有攻击迹象时 |
| 网关不查库 | 封号（`status=0`）只影响新登录 | 与第一条一起处理 |
